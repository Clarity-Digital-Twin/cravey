# BUG-034: In-flight GPS request can overwrite a later manual location selection

**Priority:** P2 (Race condition / UX correctness)
**Status:** OPEN
**Reported:** 2026-01-30
**Primary Area:** Location selection (async state)

## Problem

Location selection runs async work when the user taps **📍 Current** (GPS). If the user changes their mind and taps a preset (e.g., “Home”) while the GPS request is still in flight, the eventual GPS completion can overwrite the newer selection.

This is a classic “last async completion wins” race: **user intent should win**, not the earlier request finishing later.

## Location

- `Cravey/Presentation/Protocols/LocationHandling.swift`
  - `handleLocationSelection(_:)` starts an async request and later sets `selectedLocation`.
- `Cravey/Presentation/Views/Components/LocationSelector.swift`
  - Starts a new `Task` on every selection change without cancelling prior tasks.

## Steps To Reproduce

1. Open `CravingLogForm` or `UsageLogForm`.
2. Tap **Location → 📍 Current** (shows spinner).
3. Immediately tap **Home** (or any preset).
4. Wait for the GPS request to return.
5. Observe location selection flips back to GPS (“Current Location”) even though the user last chose “Home”.

## Expected

- The most recent user selection wins.
- If the user picks a preset while GPS is loading, the GPS request should be cancelled or ignored.

## Actual

- GPS completion sets `selectedLocation` after the user already changed it, overwriting the newer state.

## Proposed Fix

- Add cancellation/tokening for location requests in the ViewModel:
  - Store an `@ObservationIgnored` `Task<Void, Never>?` for the in-flight request and cancel it on new selections, **or**
  - Use a monotonically increasing request ID/token and only apply results if the token matches the latest selection.
- Optionally disable location chips while `isLoadingLocation == true` to avoid overlapping intents (but cancellation is still preferred).

## Acceptance Criteria

- [ ] Selecting a preset while GPS is loading never flips back to GPS after completion.
- [ ] Multiple rapid taps do not cause inconsistent final selection.
- [ ] Cancellation does not surface as an error/toast.
