# BUG-029: Export Data Missing CSV + Incomplete Payload

**Status:** OPEN
**Priority:** P1
**Files:**
- `Cravey/Presentation/ViewModels/SettingsViewModel.swift:53-78`
- `Cravey/Domain/UseCases/ExportUserDataUseCase.swift:3-35`
- `Cravey/Presentation/Views/Settings/SettingsView.swift:31-87`

## Problem

The app’s “Export Data” feature currently:
- Exports **JSON only** (no CSV option).
- Exports **cravings + usage only** (does not include motivational messages or recordings).

This is a mismatch with the master specs (export format choice + full export surface), and it can mislead users into thinking they have a complete backup.

## Current Code

- `SettingsViewModel.exportData()` always writes a `.json` file and presents the share sheet.
- `UserDataExport` only contains `cravings` and `usages`.
- `SettingsView` exposes a single “Export Data” button (no format selection UI).

## Expected

Per master specs, export should be complete and explicit:
- Support **CSV + JSON** format selection.
- Export should include **all user data types** persisted by the app (at minimum: cravings, usage; ideally also recordings + motivational messages when those features are implemented).
- UI should make the export format and coverage unambiguous.

## Fix

- Add an export format selector (CSV vs JSON) in Settings UI.
- Extend the export pipeline to:
  - Generate **CSV** for cravings + usage (at minimum).
  - Include additional data types once their repository/use-case surface exists.
- Add tests covering:
  - CSV generation correctness (headers + row counts).
  - JSON export schema versioning / completeness expectations.
