# BUG-027: Delete All Data Not Atomic

**Status:** FIXED
**Priority:** P2
**File:** `Cravey/Data/UseCases/SwiftDataDeleteAllUserDataUseCase.swift`

## Problem

Deleting “all user data” spans two storage systems:
- SwiftData records (cravings, usage, recordings, messages)
- On-disk media files (Recordings/ directory)

The current implementation is **not transactionally atomic** across those two systems, so partial failure can occur.

## Current Code

```swift
// Stage recordings directory move (reversible)
// Delete SwiftData (single save) + rollback on failure
// Commit file deletion after SwiftData succeeds
```

## Expected

Either:
- All data is deleted, or
- Failures are handled explicitly (clear user messaging + safe retry behavior) without leaving the app in a confusing partial state.

## Fix

Implemented an atomic-ish strategy with explicit error handling:
- Stage recordings deletion by moving `Documents/Recordings/` to a temporary `Recordings.__delete_pending__*` directory (fast + reversible).
- Delete SwiftData models in a single save.
- If SwiftData deletion fails, rollback the directory move so the user is not left in a partial state.
- If SwiftData succeeds, permanently delete the staged directory.

Also aligned with master spec: **only custom motivational messages are deleted; defaults are kept**.
