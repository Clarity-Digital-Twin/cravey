# BUG-027: Delete All Data Not Atomic

**Status:** OPEN
**Priority:** P2
**File:** `Cravey/Data/UseCases/SwiftDataDeleteAllUserDataUseCase.swift:16-30`

## Problem

Deleting “all user data” spans two storage systems:
- SwiftData records (cravings, usage, recordings, messages)
- On-disk media files (Recordings/ directory)

The current implementation is **not transactionally atomic** across those two systems, so partial failure can occur.

## Current Code

```swift
// Step 1: Delete files (may fail)
try await Task.detached(...) { try FileStorageManager.deleteAllRecordings() }.value

// Step 2: Delete database
try await MainActor.run { ... }
```

## Expected

Either:
- All data is deleted, or
- Failures are handled explicitly (clear user messaging + safe retry behavior) without leaving the app in a confusing partial state.

## Fix

Clarify and enforce a strategy:
- If **privacy is highest priority**, delete files first (current approach), then delete SwiftData. If SwiftData deletion fails, surface a clear error and allow retry.
- If **data integrity is highest priority**, delete SwiftData first, then files best-effort, but ensure the user is told if any media could not be removed.

In both cases, consider collecting both errors and surfacing an explicit “partial deletion” error so the UI can communicate the outcome accurately.
