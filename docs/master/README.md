# Master Documentation

These are the **authoritative** specification documents that define what Cravey IS.

**Do NOT change** product/clinical requirements in these docs without explicit approval. Technical corrections and dated “implementation notes” are allowed to keep the docs aligned with the codebase.

## Contents

| Document | Purpose |
|----------|---------|
| `MVP_PRODUCT_SPEC.md` | Product vision, features, success criteria |
| `CLINICAL_CANNABIS_SPEC.md` | Domain requirements, clinical model |
| `UX_FLOW_SPEC.md` | Screen designs, user flows |
| `DATA_MODEL_SPEC.md` | SwiftData schemas, relationships |

## Hierarchy

1. **Master** (immutable) - What Cravey IS
2. **Specs** (active) - Current implementation work
3. **Future** (deferred) - Features we're NOT building yet
