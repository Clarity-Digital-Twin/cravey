## P2 Issues (Fix Soon)

### BUG-025: StartupFailure Alert Not Shown to User

**Status:** OPEN
**File:** `Cravey/App/CraveyApp.swift:27-34`

**Problem:**
When `DependencyContainer.init()` throws `StartupFailure`, the catch block sets `_showStorageAlert = State(initialValue: false)` instead of `true`. This prevents the error alert from displaying.

**Code:**
```swift
} catch let error as DependencyContainer.StartupFailure {
    _startupFailure = State(initialValue: error)
    _showStorageAlert = State(initialValue: false)  // ← Should be true
}
```

**Impact:** Users see blank app with no indication of failure.

**Fix:** Change to `_showStorageAlert = State(initialValue: true)`

---

### BUG-026: HomeView Sheet Success Detection Race Condition

**Status:** OPEN
**File:** `Cravey/Presentation/Views/Home/HomeView.swift:58-77`

**Problem:**
In the sheet's onDismiss closure, `didSucceed` is read AFTER `cravingLogViewModel = nil` executes. The ViewModel may be deallocated before the flag is read.

**Code:**
```swift
.sheet(isPresented: $showCravingLogSheet) {
    let didSucceed = cravingLogViewModel?.didSucceed ?? false  // May be nil!
    cravingLogViewModel = nil
    // ...
}
```

**Impact:** Success toast may not appear after logging.

**Fix:** Capture success state before setting ViewModel to nil, or use completion callback.

### BUG-027: RecordingMapper Silently Downgrades Invalid Enums

**Status:** OPEN
**File:** `Cravey/Data/Mappers/RecordingMapper.swift:28-45`

**Problem:**
Invalid enum values are silently converted to defaults with only a warning log. This causes data loss during schema migrations.

**Code:**
```swift
if let parsed = RecordingType(rawValue: model.type) {
    recordingType = parsed
} else {
    logger.warning("Invalid recording type...")
    recordingType = .audio  // Silent data corruption
}
```

**Impact:** User's recording type/purpose could change without notice.

**Fix:** Throw error or add schema migration strategy.

### BUG-028: Dashboard Streak Calculation Logic Inverted

**Status:** OPEN
**File:** `Cravey/Presentation/ViewModels/DashboardViewModel.swift:92-109`

**Problem:**
"Current Streak" calculates days SINCE last usage, but in a cessation app it should represent days OF ABSTINENCE. If user logged usage today, streak should be 0, but logic shows "0" because `now - lastUsage` is 0.

**Code:**
```swift
let currentDays = max(0, calendar.dateComponents([.day], from: lastUsage.timestamp, to: now).day ?? 0)
```

**Question:** Is this logic correct, or should "Current Streak" count days between uses (gaps)?

**Impact:** Metric may confuse users about their progress.

**Fix:** Clarify metric meaning with Dr. Ray; adjust calculation if needed.

### BUG-029: Delete All Data Operation Not Atomic

**Status:** OPEN
**File:** `Cravey/Data/UseCases/SwiftDataDeleteAllUserDataUseCase.swift:16-30`

**Problem:**
File deletion and database deletion are separate operations. If one fails, data becomes inconsistent (orphaned files or dangling database records).

**Code:**
```swift
// Step 1: Delete files
try await Task.detached(priority: .utility) {
    try FileStorageManager.deleteAllRecordings()
}.value

// Step 2: Delete database (even if files failed)
try await MainActor.run {
    try modelContext.delete(model: CravingModel.self)
    // ...
}
```

**Impact:** Partial deletions leave app in inconsistent state.

**Fix:** Collect all errors, only commit database changes if file deletion succeeds, or implement rollback.
